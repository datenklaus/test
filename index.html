What this demo shows

This board runs gPTP (IEEE 802.1AS) time synchronization over a 10BASE-T1S single-pair Ethernet link. Several nodes share one multidrop bus using PLCA; one node acts as the grandmaster clock and the others discipline their local clocks to it. The goal is sub-microsecond time alignment across all nodes, shown live in the Live Monitor tab.

Roles & topology

  • Node 0 — Grandmaster (master): owns the reference clock and periodically sends Sync / Follow_Up messages (~every 125 ms).
  • Nodes 1..N — Slaves: receive Sync, measure their offset from the master and steer their own clock to match.
  • The T1S PLCA node ID is read from flash at boot and determines the role.

How a slave locks on

Each slave measures the time error Δt between its clock and the master. A PID servo then computes a frequency correction (corr_ppb) that is written to the hardware clock rate register (addend). Over a few seconds the offset converges toward zero and the clock stays locked. A corrected 1 PPS output toggles LED10 once per second — in sync across all locked nodes.

Reading the Monitor

  • Δt offset — current time error; trends to ~0 ns once locked. Hover any card for a description.
  • addend — clock rate word the servo tunes.
  • corr_ppb — servo output in parts-per-billion.
  • mpd_ns — measured link (path) delay.
  • sync_period — interval between Sync messages (~125 ms).
  • The chart plots Δt on a fixed ±200 ns scale; the table keeps recent raw rows.

Tuning the servo (PID)

The PID servo settings panel reads and changes the servo gains live via ptp servo params Kp Ki Kd. A larger Kp reacts faster but can overshoot; Kd adds damping; Ki removes steady-state bias. Start from a preset and watch the offset chart respond.

Getting started

  1. Connect the board's USB serial port and click Connect (115200 baud).
  2. Click Enable Log to stream the per-Sync table (ptp log def on).
  3. Watch the Δt offset converge; adjust the PID gains if desired.
